H32 Mechanism and execution replication
Objective: explain H31 quality/cost gains without confusing learned control with fixed evidence operations; evaluate numerical/run variation.
Frozen data: all 800 H31 2Wiki observations (now exposed; never relabel as a new independent confirmation), same corpus/evaluator/model revisions and greedy 128-token answer prompt.
Unit A: one new complete bm25_rewrite request on every one of the 800 questions. Randomized question schedule seed 1432. All writer/ranker/retrieval/reader costs charged. Retain all outcomes, compare with H31 baseline, no choosing the better run.
Unit B: all 81 H31 relation-rule accepted questions, selected by rule acceptance only, including all 58 prefix-rule accepted. Four reader contexts: initial5, rule_context, rule_evidence_documents (complete documents cited by the rule, not gold supporting passages), H31 rewrite_final10. Three independent 8B executions of each context, randomized request order seed 1432, 972 new reader calls. Identical prompts except provided documents; no new instruction or answer format. Context rows that coincide are still executed independently. Gold and historical model answers excluded from payload.
Interpretation: conditional mechanism study on accepted questions, not an estimate of general dataset accuracy or independent sample size 972. All intervals cluster by question and average repeated executions before comparison. Primary mechanism contrast within 58 prefix-accepted questions: rule versus reader on identical initial5 evidence; secondary: reader initial5 versus rewrite_final10 and evidence-only. Relation-added23: compare initial5 and acquired rule context, then rule versus reader with same context. All H32 quality contrasts are post-H31 exploratory and unadjusted.
Shared-fallback sensitivity: compute frozen rule policies using each complete baseline run as the shared fallback. This is offline coupling for attribution, not newly measured end-to-end latency. No replacement of H31 primary outcome or interval.
Metrics: official F1 and EM, captured FLOPs, full baseline measured request latency, reader-only mechanism latency, context caps and generation caps, input/output variation. Do not pool hardware runs or mix reader-only timing with full pipeline timing.
Source review: for each mechanism contrast inspect up to 2 first hash-ordered discordant questions with complete retrieved documents; if no discordance inspect first hash-ordered question. Include both improvement and harm directions when present.
Boundaries: same pinned Qwen3 4B/8B, BF16 SDPA TF32 off, H100. No policy fitting, parser expansion, quality-directed retries, or threshold search. Setup can reuse verified caches; one engineering repair allowed without scientific changes, preserving failed records. Native CUDA outside provider vault tracer; only storage uses official provider wrapper.
